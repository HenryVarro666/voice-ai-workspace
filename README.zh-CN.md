# Voice AI 工作区

[English](README.md) · **简体中文**

**打造能被插话打断、跟上最新意图，并把正确事实说清楚的语音 Agent。**

这是四个关联代码仓库的文档总入口，把产品目标、实验与采用决定串起来。项目目前属于研究与工程原型；部署、自动检查和人工接受分别记录。

## 想解决什么问题，用于什么场景

语音助手不能只追求第一块音频快：用户说话更正时，它需要停止旧回答，保留姓名和数字，按最新意图确认操作。可选数字人也应清楚保留相同语音。

当前主展示是模拟预约助手：请求时段 → 播报时插话更正 → 明确确认 → 用同一编号改期。中文桌面语音助手另作工程基线。没有连接真实日历或临床系统。

## 当前证据支持什么结论

| 问题 | 实际结果 | 决定与边界 |
|---|---|---|
| 中文语音能否走完整助手界面？ | 最近 17 轮合成输入：新会话首次 3.75 秒，热轮 1.04–2.01 秒 | 起点为输入最后有声，终点为浏览器首有声排定；不含硬件、真人或严格冷启动 |
| 取消后能否避免排队推理浪费？ | 独立候选首 PCM 前，消费者关闭→生成退出中位 1948.4→63.3ms | 继续取消工作；不是普通首声普遍提速，也未部署生产 |
| 原生预约播报能否更快？ | 已采用缓存原型：工具更新→网关首有声 PCM 中位 3.338→1.552 秒，共十次 | 保留此基线；不含识别、工具查询等待及音频硬件 |
| 亚秒级预约播报是否可采用？ | 0.898 秒预填充未过日期门禁；后续 0.868 秒节拍候选仍有人工确认的错误/含糊日期 | 两个候选都不采用；计算一致和 ASR 检查不能代替事实听清 |
| 筛选/加权训练能否改善 ASR 内容保留？ | 最新四臂×三 seed：362 条 MER 为 9.7315/9.8353/9.8353/10.1329% | 未证明可靠筛选/加权收益；原生/全1对照仅在已测 batch1 条件相同 |
| 只改提示能否改善数字人表情？ | E1c 两段受控新片＋六份同步副本，仍见手入画与强调张嘴 | NEEDS WORK；按门槛跳过收尾生成；人工音画接受待验 |

各行数据集与计时边界不同，不能合成一个速度或质量分数。完整协议、失败与不确定区间见[实验地图](EXPERIMENTS.md)。

## 实验如何记录与展示

1. **README：** 解释产品问题、选中方法、最有证据的结果与下一项决定。
2. **实验索引：** 每个假设一行，记录比较、结论、采用状态和链接。
3. **详细记录：** 保留冻结计划、源码/模型版本、输入及样本数、结果、失败、验证与局限。新结论明确替代旧结论，旧记录继续作为历史。

公开仓库保存代码、合成元数据、汇总指标和图表。凭据、权重、原始/生成音视频、完整私人转写和运行日志留本地。[公开范围](PUBLICATION.md)说明已发布证据与仅本地文件的区别。

## 正在探索与下一步

- 先让 TTS 在发送停滞时有明确期限，再完成共锁兼容和实际替换/恢复验收。
- 用冻结的真实入口回归解决预约起句和日期清晰度，再追求更低延迟。
- 冻结 tokenizer 保存/加载与混长 batch 契约；先在 train/dev 上核对参考和声学分歧，再做下一轮训练。
- 先人工比较数字人同步，再冻结一种更强构图/动作控制假设。
- 真人麦克风、耳机、外放回声分别验收，不以合成输入代替。
